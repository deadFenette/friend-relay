## 2. Визуальная полировка превью (скриншоты/картинки)

Визуальный аудит (`scripts/visual_audit_web.py`, скриншоты всех
ключевых экранов в двух темах) вскрыл три неаккуратных состояния —
все закрыты:

### 2.1 Скелетон вместо «сломанной картинки» при загрузке
Пока превью качается, `<img>` был без `src` — Chromium рисовал внутри
бокса «сломанную картинку» и alt-текст: выглядело как ошибка у
пользователя. Теперь:
- на время загрузки `src` = прозрачная 1×1 GIF-заглушка
  (`IMG_BLANK` в images.js) — никакой браузерной «поломки»;
- CSS `.img-wait` рисует скелетон: пунктирная рамка + бегущий
  шиммер (`@keyframes imgSkeleton`, градиент `surface2↔surface3`);
- цвета — на токенах темы, работает во всех 6 темах и 2 скинах.

### 2.2 Аккуратный фейл при ошибке сети
Если `/download` упал — раньше тот же «сломанный» вид. Теперь
`imgMarkFail()` (единая точка для всех копий превью этого file_id):
пустой `alt`, нейтральный пустой бокс (пунктир, спокойный фон) и
честный тултип: *«превью не загрузилось — файл можно скачать по
ссылке»*. Файл по-прежнему доступен ссылкой в бабле.

### 2.3 Битые данные (новая защита)
Обнаружено при аудите: если байты приходят, но не декодируются
(обрыв файла при передаче, не-картинка с именем `.png`), `objectURL`
проставлялся, класс был `img-ready`, а Chromium рисовал «сломанную
иконку» — и в ленте, и НА ВЕСЬ ЭКРАН в лайтбоксе. Теперь:
- `img.onerror` в превью → `imgMarkFail` (честный фейл, п. 2.2);
- `img.onerror` в лайтбоксе → лайтбокс НЕ зависает на «сломанной
  иконке»: сам закрывается, кеш помечает file_id как негодный
  (сервер не долбится повторно), все копии превью помечаются фейлом,
  пользователь получает тост: *«не удалось показать картинку — файл
  можно скачать по ссылке»*.
