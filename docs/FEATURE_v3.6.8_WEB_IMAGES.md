## 1. Скриншоты в веб-чате (главное)

Проблема: в веб-клиенте не было способа кинуть скриншот — файлы заливались
только через вкладку «Файлы», картинки в чате приходили «скрепкой с именем».

Решение — модуль web_client/images.js:

1. Загрузка:
   - кнопка со скрепкой в композере чата (accept="image/*", можно несколько);
   - Ctrl+V: скриншот из буфера обмена уходит сразу (обработчик paste на
     document, только когда открыт чат и есть сессия; текстовые вставки
     не трогаются).
   - Файл идёт на /send_file — тот же механизм, что у «Файлов»: в ленту
     приезжает обычное file-событие, его видят и веб, и Qt-клиент.
2. Превью в ленте: file-события с именем-картинкой (png/jpg/jpeg/gif/
   webp/bmp/svg) рисуются уменьшенной копией в бабле. <img> не умеет
   слать заголовки (X-Relay-Key нужен при включённом ключе), поэтому
   картинка тянется fetch'ем с baseHeaders() и превращается в objectURL.
   objectURL кешируется по file_id (вытеснение, максимум 80): диффы
   канала, поиск, подгрузка истории не перекачивают одну и ту же
   картинку. Ошибка загрузки — состояние «не открылась», повторных
   попыток-долблений нет. Работает и в ЛС (/dm_download — приватный
   маршрут, сервер проверяет, что ты отправитель или получатель).
3. Лайтбокс поверх чата:
   - клик по превью → полноэкранный оверлей (z-index 200) со шапкой
     (имя файла, индикатор масштаба, кнопки зум−/зум+/скачать/крестик);
   - зум: клик по картинке 1x ↔ 3x в точке клика (transform-origin под
     курсором), колесо мыши 1x–8x с якорем под курсором, кнопки ±;
   - пан: перетаскивание при увеличении (Pointer Events, touch-action);
   - закрытие: Esc, крестик, клик по фону. Скролл body блокируется.
4. Темы (обязательно по ТЗ): весь хром — на токенах style.css
   (--surface/--text/--border/--shadow-pop...). Фон оверлея — отдельная
   переменная --lb-backdrop со СВОИМ значением на каждую тему:
   Aurora rgba(6,7,10,.86), Lukewarm Ocean rgba(4,14,19,.88), Snow
   rgba(240,242,246,.9), Cherry Grove rgba(244,234,226,.9), Sakura
   rgba(248,238,242,.9), Crème Brûlée rgba(246,238,221,.9); скин
   «Ночник» — rgba(7,16,21,.9), скин «Крем-брюле» — светлый
   rgba(246,239,225,.92). Светлые темы получают светлый оверлей, а не
   чёрную простыню поверх белого интерфейса.
5. Безопасность: имя файла — только textContent (никакого innerHTML),
   src картинки — только наш собственный objectURL, внешние URL не
   вводятся; ревок blob'ов на pagehide и при вытеснении из кеша.

## 2. Голос (веб): повторная проверка + две новые проверки

«Проверь микрофон ещё раз, но для ВЕБ» — проверено НАСТОЯЩИМ Chromium,
а не симуляцией: новый скрипт scripts/web_voice_browser_e2e.py поднимает
реальный RelayServer (мост + микшер), открывает ДВА независимых контекста
Chromium с fake-mic, подключает их через настоящий web_client (voice.js +
voice-worklet.js) и замеряет 12 проверок:

  - getUserMedia: трек жив, AudioContext 48000/running;
  - захват: sentFrames растёт (микрофон шлёт 20мс-кадры);
  - приём у собеседника: recvFrames растёт;
  - звук не пустой: в плейауте есть кадры с RMS > 120;
  - «бурундук»-детектор: в кадрах плейаута НЕТ внутрикадрового
    повторения (все 8 блоков по 128 сэмплов идентичны) — баг v3.6.6
    давал бы ~100% таких кадров; сейчас 0;
  - живая волна: разброс RMS между кадрами;
  - обратное направление B→A — симметрично;
  - mute: после промывки тракта (1с) у собеседника одни silence-кадры;
  - предупреждений голоса нет, JS-ошибок нет.

Итог: 12/12 PASS. Голосовой тракт веба подтверждён целиком — симптомы
пользователя («не слышит», «бурундук») закрыты фиксами v3.6.7, что теперь
доказано браузерным E2E.

Две добавленные ПРОВЕРКИ в voice.js (v3.6.8):
1. Сторож suspended AudioContext в voiceTick: если контекст остался
   suspended (автоплей-политика после автореконнекта/пробуждения
   фоновой вкладки), пробуем resume(); не удалось — в статусе честное
   «звук заблокирован браузером — кликни по странице» вместо молчащего
   «подключено без звука».
2. Подсказка «микрофон пока молчал»: ровно один раз за сессию, если
   прошло 30с с подключения, микрофон не мьючен, а живого голоса
   (RMS > 300) не было ни разу — при мёртвом/не-том устройстве человек
   говорит в пустоту и не знает об этом. При появлении голоса подсказка
   гаснет. Сброс — на отключение/новую сессию.
