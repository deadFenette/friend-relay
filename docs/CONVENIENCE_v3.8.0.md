# v3.8.0 — Пак удобств: поиск по всей истории, drag&drop файлов, ОС-уведомления

Дата: 2026-10-04 · База: v3.7.2 · Область: веб-клиент + сервер (один новый GET-роут)

## 1. Поиск по всей истории

### Сервер

- **`EventStore.search_events(query, limit=50, author="")`** — новый метод
  `lib/domain/event_store.py`. Регистронезависимая подстрока по тексту
  сообщений и именам файлов. Сканируется **весь** `history.jsonl` — включая
  события, давно вытесненные из 5000-элементного кеша (тот же шаблон чтения,
  что у `get_pinned_messages`). Дельты `edit` переигрываются: ищется
  **актуальный** текст правленого сообщения. Tombstone-удаления исключаются.
  Зашифрованные сообщения **честно пропускаются**: сервер физически не может
  их прочитать (E2E), осмысленной подстроки в шифротексте не бывает. Ответ —
  последние `limit` (10..100) совпадений от старых к новым.
- **`ChannelManager.search_messages(...)`** — тот же контракт по всем
  `channels_dir/*.jsonl` (первая строка-метаданные пропускается), опциональный
  фильтр по каналу; у каждого результата поле `channel`.
- **`RelayServer.search_history(...)`** — слияние обоих источников по
  глобальному `seq` (нумерация едина, поэтому общий чат и каналы честно
  перемежаются), возвращает `{results, total}`.
- **`GET /search?q=&author=&limit=`** (`lib/server/http_api.py`) — q минимум
  2 символа (иначе 400 с внятной ошибкой), limit клампится 10..100.

### Клиент (`web_client/search.js`, новый модуль)

- Кнопка-лупа **#btnHist** в шапке чата (рядом с пинами) открывает панель
  **#histPanel** — каркас переиспользует `.pinpanel`, стили на токенах тем
  (скины подхватываются автоматически). Внутри: запрос, необязательный
  фильтр по автору, кнопка «Найти», счётчик-статус, список результатов.
- Результат: автор (в цвете аватара), время, сниппет с **подсветкой
  совпадения** (`.hl`, собран DOM-узлами — ни одного `innerHTML` с данными),
  у канальных результатов — чип **#канала**.
- **Прыжок**: если бабл уже в ленте — `jumpToSeq` (подсветка `.flash`).
  Если глубже — докачивается контекст `/events?before=seq+1&count=40` и
  вставляется над текущим верхом ленты тем же механизмом, что у подгрузки
  скроллом (с сохранением позиции чтения), затем подсветка. Для результатов
  из каналов: канал открывается сам, дожидается своего канального окна;
  вне окна — честное «глубже канального окна» (сервер не умеет `before`
  для каналов, а чужой общечатовский контекст вокруг seq вставлять нельзя).
- Устаревшие ответы отбрасываются счётчиком запросов (`HIST_REQ`, по образцу
  `S.chanReq`); повторное открытие панели с уже набранным запросом автоматически
  перерисовывает результаты. Esc закрывает панель.
- ЛС **не ищутся** сознательно: они приватны и хранятся попарно — поиск по
  ним отдельная задача бэклога.

## 2. Бонус-фикс: подгрузка истории скроллом вверх

`loadOlderMessages` (v1.9.5) проверял ответ `/events?before=…` как
`if (!json || !json.ok || !json.events) return;` — но сервер `/events`
**вообще не отвечает полем `ok`** (ни в одном режиме). `json.ok` всегда
`undefined`, проверка всегда истинна — каждый батч **молча выбрасывался**,
скролл-подгрузка не работала вовсе. Основной цикл `pollTick` от этого не
страдал: он использует строгую форму `json.ok === false`. Исправлено на
строгую форму в обоих местах (`chat.js`, `search.js`). Найдено браузерным
E2E при отладке глубокого прыжка — сквозной тест ловит оба потребителя.

## 3. Drag&drop файлов в чат

`web_client/images.js`:

- `uploadChatImage` обобщена в **`uploadChatFile`**: любой файл уходит тем же
  путём `/send_file` (X-Relay-Filename + SHA256 + HMAC по байтам, стриминговая
  проверка на сервере). Картинки — прежний путь с превью и лайтбоксом;
  остальное — обычное file-событие, которое видят и веб, и Qt-клиент.
- **`uploadChatFiles(files)`** — без фильтра по типу (в отличие от Ctrl+V,
  где картинки фильтруются осмысленно: буфер кладёт их без имени).
- Document-хендлеры `dragenter/dragover/dragleave/drop` со счётчиком глубины
  (leave срабатывает на каждом пересечении границ дочерних элементов).
  Реакция **только на файлы** (`dataTransfer.types` содержит `Files`) —
  перетаскивание текста внутри страницы не перехватывается.
- Активна только при открытой вкладке «Чат» и живой сессии.
- Оверлей **#dropOverlay** — пунктирная рамка поверх панели с подписью
  «Отпусти файл — отправим в чат»; `pointer-events:none`, поэтому `drop`
  доходит до document-хендлера без посредников. Стили на токенах тем.

## 4. ОС-уведомления

`web_client/notify.js`, новый модуль:

- **`osNotify(title, body, tag)`** — показывает системный попап только когда
  вкладка **не активна** (`document.hidden`); клик по попапу возвращает окно
  чата (`window.focus()`); `silent: true` — звук уже делает `notifyBeep`.
- **Разрешение запрашивается только по жесту пользователя**: при включении
  звука колокольчиком (#btnNotify в main.js) — один раз; отказ не мешает
  звуку, просто не будет попапов. Никаких запросов «по собственному
  желанию» при загрузке страницы.
- Тумблер `wr_osnotify` в localStorage раздельный со звуком (`wr_notify`).
- Хук в `addBubble` (chat.js) — рядом с `notifyBeep`: имя автора + сниппет
  (файлы — именем файла). Хук в `dmBadgeTick` (dm.js) — новое ЛС: попап от
  имени собеседника, **dedup** через `DM.osLastNotified` (не чаще одного
  уведомления на новое сообщение от каждого) + прежний бейдж на вкладке.
- Тестовый хук: успешная отправка пишется в `window.__frLastNotify`
  ({title, body, tag}) — E2E проверяет факт и содержимое уведомления.
- Известное ограничение окружения: headless Chromium держит
  `Notification.permission = "denied"` и `grant_permissions` на него не
  влияет — поэтому E2E стабит `window.Notification` целиком (init_script),
  проверяя именно логику notify.js.

- **scripts/web_convenience_e2e.py** — 20 проверок в Chromium против
  реального сервера и реального web_client. Журнал наполняют 205 филлеров от
  **трёх фантомных сессий** (Python: `/ping` → token, подпись
  HMAC-SHA256(token, body) — та же схема, что у `apiPost`; честно уважают
  token-bucket антифлуда 30+5/с: три имени ≈ 15 сообщений/с).
  Сценарии: поиск с фильтрами и пустым результатом; глубокий прыжок к
  сообщению, уехавшему за пределы хвоста ленты (докачка контекста + `.flash`);
  канальный результат с чипом и прыжком; drop `.txt` (file-бабл у обеих
  сторон) и `.png` (превью `.imgprev`); ОС-уведомления (гейт hidden,
  содержимое, dedup ЛС); ноль JS-ошибок.
- **Регресс**: 48 файлов, 1626 проверок, 0 FAIL. Голосовой тракт-E2E 14/14,
  voice UX E2E 16/16, плейаут 8/8, визуальный аудит — зелёные.
