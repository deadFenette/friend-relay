# Демонстрация экрана со звуком (v3.6.0, вкладка «Экран»)

## Что это

Показ своего экрана (всего / окна / вкладки браузера) друзьям в веб-клиенте
Friend Relay — со звуком. Ведущий и зрители видят друг друга в реестре
«Сейчас показывают», счётчик зрителей — по факту P2P-подключения.

## Как это устроено (почему без библиотек)

Картинка и звук идут через **WebRTC P2P** — напрямую от браузера ведущего к
браузерам зрителей. Захват делает `getDisplayMedia`, кодирование и транспорт —
встроенный в Chromium WebRTC (BSD-подобные лицензии). **Сервер Friend Relay
никакое медиа не качает**: он только пересылает служебные JSON хендшейка
(offer/answer — «сигналинг») через уже существующий HTTP API. Поэтому:

- ноль новых зависимостей в requirements.txt;
- ноль новых портов (сигналинг ходит через основной порт 8420);
- ноль нагрузки на хост при 1+ зрителях (медиа не через него).

Готовые библиотеки (PeerJS MIT, simple-peer MIT, mediasoup ISC, LiveKit
Apache-2.0) отвергнуты осознанно: PeerJS требует Node.js-сервер, mediasoup —
Node/C++ воркер, LiveKit — отдельный Go-сервис; simple-peer заброшен с 2022.
WebCodecs-самопис — крайний случай (свой протокол фрагментации, джиттера,
A/V-sync) — не понадобился.

## Как показать экран

1. Открой вкладку **«Экран»** (в скинах «Ночник»/«Крем-брюле» — карточка
   «Экран» в колонке «Сейчас»), нажми **«Показать свой экран»**.
2. В диалоге браузера выбери, что показывать. Чтобы был звук:
   **выбери «Весь экран» и поставь галочку «Также передавать звук системы»**
   (Chrome/Edge на Windows). Звук вкладки передаётся при показе вкладки.
3. Готово — друзья видят анонс в чате и кнопку «Смотреть» на вкладке «Экран».
4. Закончить — кнопкой «Закончить показ» или «Прекратить показ» в панели
   браузера (подсказка сервера гаснет сама через 30 секунд тишины).

## Ограничения звука (это браузеры, не мы)

| Браузер | Системный звук | Звук вкладки |
|---|---|---|
| Chrome/Edge, Windows | да (галочка в диалоге) | да |
| Chrome, macOS | вкладка; система — с ~Chrome 141 | да |
| Firefox | нет (аудиотрека не создаётся) | нет |
| Safari | нет | нет |

Если аудиотрек не пришёл, панель честно предупредит: «Звука нет…».
Показываете системный звук — наденьте наушники, иначе голосовой чат попадёт
в показ дважды.

## Сеть (ZeroTier, NAT)

Медиа идёт P2P: обычно прямой путь через ZeroTier/локалку. Chrome маскирует
локальные адреса mDNS-именами (.local), которые не резолвятся между машинами,
поэтому клиент подкладывает публичные STUN-серверы (Google/Cloudflare) — они
дают рабочие srflx-кандидаты. Симметричный NAT с двух сторон может заблокировать
прямой путь — тогда соединение не установится (зритель увидит «связь не
установилась»); план развития — TURN/SFU (например, MediaMTX, MIT) рядом с
хостом, в v3.6.0 не входит.

## Маршруты API (всё за access_key + подпись X-Relay-Auth)

| Маршрут | Что делает |
|---|---|
| `GET /screen/info` | реестр живых показов: [{from, title, started, viewers}] |
| `POST /screen/publish` | ведущий: {on:true} — анонс/heartbeat (раз в 8с), {on:false} — конец; анонсы дублируются строкой в общий чат |
| `POST /screen/signal` | релей сигнала WebRTC: {to, data:{type:"hello"\|"offer"\|"answer"\|"bye", sdp?}} |
| `GET /screen/poll?since=N` | забрать свои сигналы (персональная почта, AUTH_REQUIRED_GET) |
| `POST /screen/watch` | зритель подтвердил P2P-подключение: {to, on} — счётчик «Смотрят» |

Лимиты сигналинга (screen/config.py): 256 писем на получателя (переполнение
выкидывает самое старое), 256 КБ на письмо, TTL 90 с, показ живёт 30 с без
heartbeat. Счётчики — в `/server/stats` (блок `screen`).

## Тесты

`python tests/test_screen_v360.py` — 49 проверок: ScreenHub (реестр, почта,
переполнение, TTL по фейковым часам), живой сервер (все маршруты, 403 без
подписи, анонсы в чат, /server/stats), каркас веб-клиента (вкладка, скрипты,
скины, иконка, стили).
