# FIX v3.6.7 — «собеседник не слышит» + «слышит как бурундука»

Дата: 2026-09-29
Симптомы от пользователя: собеседник не слышит; слышит плохо — «как
бурундука». Три независимых корня, все пойманы ЗАМЕРАМИ на живом
конвейере (не на глаз), все исправлены.

## Как искали

Полный прогон стека на реальном коде:

1. **E2E-симуляция серверного тракта** (микшер + мост + клиенты обоих
   протоколов): Qt(opus)→Qt, Web(PCM/WS)→Qt, Qt→Web, Web→Web — 4/4 PASS,
   150 кадров туда-обратно, частота и размеры точные. Вывод: микшер,
   мост и переговоры кодека корректны — баги на КЛИЕНТСКИХ сторонах.
2. **Настоящий Chromium + фейковый микрофон** (Playwright,
   `--use-fake-device-for-media-stream`): реальный voice-worklet.js,
   реальная логика voice.js, реальный мост — и замер содержимого кадров.
3. **Движок Qt с фейковым sounddevice**: колбэки захвата нестандартных
   размеров и с сигналами разной громкости — до реального микшера.

## Корень 1 — «бурундук» (веб-клиент, захват)

**Файл:** `web_client/voice-worklet.js`, процессор `VcCap`.

Было:
```js
process(inputs){
  const ch = inputs[0] && inputs[0][0];
  if (ch){
    this.b.push(ch);            // ССЫЛКА на буфер Chrome
    ...
    if (this.n >= 960){
      const o = new Float32Array(this.n);
      for (const c of this.b){ o.set(c, k); k += c.length; }  // копия ПОЗЖЕ
```

По спецификации AudioWorklet массив `inputs` валидён ТОЛЬКО внутри
текущего вызова `process()`. Chrome переиспользует ту же память под
следующий рендер-квант. Мы копили ссылки и копировали при флеше батча —
к этому моменту все 8 накопленных чанков показывали ОДИН И ТОТ ЖЕ
(самый свежий) кусок. Микрофон превращался в «128 сэмплов, повторённые
8 раз» — жужжащий «бурундук».

**Замер в Chromium** (фейковый тон, 50 батчей): dup_ratio = **0.875**
(7 из 8 чанков идентичны — математическая сигнатура алиасинга памяти).

Стало: `this.b.push(new Float32Array(ch))` — копия немедленно.
После фикса dup_ratio = 0.42 (периодичность самого тона), идентично
контрольной исправленной версии.

## Корень 2 — «не слышно» (Qt-клиент, произвольный blocksize)

**Файл:** `voice/client/engine.py`, `_audio_in_callback`.

`blocksize=960` у PortAudio — это ХИНТ, а не гарантия: ALSA/PulseAudio
и часть драйверов Windows отдают колбэки произвольного размера
(240/480/1024...). Блок уходил в сеть ОДНИМ FRVC-кадром, а микшер
принимает строго 1920 байта (20мс/48кГц): всё прочее считалось «odd» и
отбрасывалось (voice/mixer.py — защита от старых версий).

**Замер:** 200 колбэков по 480 сэмплов → у слушателя **0** голосовых
кадров (только keepalive-тишина) при живом соединении.

Стало: аккумулятор захвата (`_cap_pending` + `_cap_lock`): байты
микрофона копятся и режутся на строгие 20мс-кадры независимо от размера
блоков (симметрично веб-клиенту `VC.pend` и плейауту `_tail`).
Проверено: 240/480/1024/960 и смешанные блоки — поток всегда
выровнен, `odd = 0`.

## Корень 3 — «не слышно» (тихий микрофон, абсолютный порог VAD)

**Файлы:** `voice/dsp.py` (новый `AutoLevel`), `voice/client/capture.py`.

`VAD_THRESHOLD = 300` — АБСОЛЮТНЫЙ порог «это речь», рассчитан на
обычный микрофон (речь RMS ~2000-5000). Тихие микрофоны (ноутбучные без
системного усиления) дают речь RMS 150-250: гейт не открывался, все
кадры уходили с флагом silence — собеседник слышал ТИШИНУ, хотя человек
нормально говорил.

**Замер:** речь RMS 150/200/250 → **0** кадров с audible-звуком.

Стало: `AutoLevel` (АГС-lite) в цепочке MicChain: HighPass → **AutoLevel**
→ SoftGate. Тихая речь тянется к ~3000 RMS (усиление до ×32, скорость
подъёма ~1-2с), нормальные/громкие микрофоны не трогаются (gain = 1,
ослабления нет). Речь не даёт шумовому полу подняться на себя, gain в
тишине возвращается к 1, усиленный шум по-прежнему гейтится.

**Замер после фикса:** та же речь RMS 200 → 189/300 audible-кадров,
сквозной тест до микшера — audible=41 (было 0).

## Дополнительные защиты (по принципу «добавь проверки»)

- **Мост** (`voice/bridge.py`): PCM-кадр не 1920 байт больше НЕ уходит
  браузеру (voice.js режет вход по 960 сэмплов, чужой хвост дал бы
  сдвиг волны) — теперь кадр пропускается с предупреждением в лог.
- **voice.js**: протухший `deviceId` микрофона (устройство вынули) больше
  не роняет подключение намертво — сначала пробуется системный
  микрофон, выбор сбрасывается, пользователь предупреждается.
- **voice.js**: края ресемплера 44.1к больше не интерполируются «в ноль»
  (микропровал волны на каждом 20мс-стыке) — край дублирует сэмпл.
- **Qt-диалог**: статус показывает подсказку «микрофон очень тихий
  (усиление ×N) — подними уровень в системных настройках», когда АГС
  вышла на потолок; `get_stats()` отдаёт `mic_gain` и `cap_overruns`.
- **requirements.txt**: websockets `<17` (v16 проверена этой версией).
