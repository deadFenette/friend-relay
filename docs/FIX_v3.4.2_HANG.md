# Friend Relay v3.4.2 — ФИКС ЗАВИСАНИЯ (намертво)

## Диагноз — что именно виснуло

Ты прав: баг был связан с фиксом синхронной музыки. Но не один, а **два
независимых механизма зависания**, которые твой фикс синхронизации
(200-мс поллинг + запись состояния на диск) свёл вместе.

### Механизм 1 — дисковые записи ПОД общим локом музыкального бота

`lib/bots/base.py::set_data()` писал `music_data.json` на диск СИНХРОННО
при каждом вызове. Музыкальный бот зовёт `set_data` по 2–4 раза на каждое
действие (play = state_version + track_id + position; seek; очередь;
громкость). А лок бота при этом держат:

- `GET /music/sync` — твой новый fast-sync поллит каждые 200 мс с каждого
  клиента первые 12 секунд трека (5 запросов/с × N друзей);
- `_Poller` в server_gui.py — каждые 1.5 с;
- фоновый цикл авто-перехода трека — каждую секунду.

**Замер на симуляции Windows (Defender+HDD, запись 40 мс):** один жест по
слайдеру громкости = 30 записей = 1257 мс блокировки GUI-потока; p95
`/music/sync` у клиентов вырастал с <5 мс до 1182 мс. Очередь из потоков
HTTP-сервера росла, окно Windows помечало «Не отвечает» — «виснет намертво».

### Механизм 2 — блокирующие вызовы в GUI-потоке Qt

- **`server_gui.py::_on_start`** звал `RelayServer(...)` + `relay.start()`
  прямо в GUI-потоке. Внутри: генерация TLS-сертификата RSA-2048 —
  **в твоём же `_dbg2.log` замерено 84.57 секунды**, плюс
  `get_interfaces()` (netsh-подпроцесс + `getaddrinfo(hostname)` +
  `connect(8.8.8.8:80)`) **БЕЗ таймаутов** — при VPN/DNS может висеть
  вечно. Это твоё «python server_main.py → полная тишина» из
  debug-server-startup-hang.md (гипотезы H1/H2/H4 подтвердились все).
- **`settings_screen.py`** (Qt-клиент, режим хоста) — та же история.
- Кнопки музыки (`api_play/pause/skip/rescan`) и слайдер громкости тоже
  звали api_* прямо в GUI-потоке — ждали лок бота и диск.
- `QTimer.singleShot(300, _check_vpn_conflict)` — третий вызов
  `get_interfaces()` в GUI-потоке через 0.3 с после открытия окна.

## Как применить

1. Закрой сервер и GUI.
2. Скопируй файлы из этой папки в корень проекта **с сохранением путей**:
   - `server_gui.py` → в корень
   - `lib\bots\base.py`, `lib\net_utils.py`, `lib\relay_server.py`
   - `lib\server\tls_util.py`
   - `qt_app\screens\settings_screen.py`
   - `web_client\music.js`
3. Удали старый RSA-сертификат, чтобы пересоздался быстрый ECDSA
   (одноразово, необязательно — старый RSA тоже работает):
   `relay_data\host\tls_cert.pem` и `tls_key.pem`.
4. Запусти как обычно: `RUN_SERVER_GUI.bat` / `RUN.bat` / `python server_main.py`.
